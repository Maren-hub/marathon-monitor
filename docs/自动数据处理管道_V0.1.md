# 自动数据处理管道 V0.1

## 它解决什么问题

本模块把模拟数据和未来实测数据统一为相同的数据结构，并自动完成：

1. 字段类型和基础合理范围校验；
2. 按 60 秒时间窗口对齐数据；
3. 按赛段汇总手环数据；
4. 融合手环、无人机、GIS和环境数据；
5. 将不同单位的指标转换为 0～1 原型特征；
6. 计算聚集风险和健康风险；
7. 推荐监测任务与处置单位。

当前规则版本为 `prototype-v0.1`。参考范围、风险权重和任务阈值只用于流程验证，尚未经过真实赛事、医学或人群安全研究验证。

## 代码位置

- `backend/app/pipeline_schemas.py`：统一输入、输出和字段校验；
- `backend/app/processing_pipeline.py`：时间对齐、融合、特征、风险与任务；
- `backend/app/main.py`：对外接口；
- `data/pipeline_sample.json`：可直接运行的四源示例；
- `scripts/send-pipeline-data.py`：批量发送标准JSON文件。

## 使用方法

先启动后端，再在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe .\scripts\send-pipeline-data.py
```

脚本会一次发送整批数据，不需要逐条录入，并显示每个赛段的风险与任务建议。

前端平台顶部提供“模拟推演 / 接入数据”切换。选择“接入数据”后：

- 已接入赛段使用管道计算的人数、风险、监测重点和推荐任务；
- 尚未接入的赛段保留原演示数据，并明确标记为“模拟补位”；
- 右侧显示数据置信度、规则版本和建议响应单位；
- 页面每3秒自动读取一次最新处理结果。

也可以打开 <http://127.0.0.1:8000/docs> 使用以下接口：

- `POST /api/pipeline/ingest`：提交一批多源数据；
- `GET /api/pipeline/segments`：查看自动处理结果；
- `GET /api/pipeline/rules`：查看当前规则、权重和原型声明；
- `POST /api/pipeline/reset`：清空本轮内存数据。

## 真实数据怎样接入

真实数据应先由对应适配器转换为与 `pipeline_sample.json` 相同的字段：

```text
手环/手机      → wearable 数组
YOLO识别结果   → uav 数组
温湿度设备     → environment 数组
GIS属性表      → gis_segments 数组
```

之后统一提交到 `/api/pipeline/ingest`，后续处理不需要因数据来源改变而重写。

早期离线实验可以先将Excel转换为标准JSON；实时设备可以直接向接口发送JSON。后续应继续增加Excel导入适配器、MQTT设备适配器、YOLO推理结果适配器和数据库持久化。

## 当前限制

- 使用内存保存数据，后端重启后记录会清空；
- 多架无人机同时观测同一区域时，只选择同一时间窗口内质量最高的一条，尚未处理视野重叠；
- 只有四类数据齐全时才计算风险，缺少来源的记录会标记为 `partial`；
- 风险分值是原型信号，不是事故概率或医学诊断；
- 地图上的运动员和无人机实体仍由模拟器提供，接入模式当前只覆盖赛段级人数、风险、策略和任务。
