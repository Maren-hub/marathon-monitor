# 团队协作与新电脑运行指南

## 1. 当前阶段目标

目前四人分工尚未确定。所有成员先完成以下共同任务：

1. 接受 GitHub 私有仓库邀请。
2. 在各自电脑克隆项目。
3. 安装依赖并成功启动平台。
4. 测试三类模拟事件和重置功能。
5. 记录自己电脑上的安装问题。

在负责人宣布任务分配前，不直接修改或推送 `main` 分支。

## 2. 仓库包含的内容

- `backend/`：FastAPI 接口、实时推送、模拟器和测试。
- `frontend/`：Vue、Cesium 页面和前后端通信。
- `data/demo_scenario.json`：合成赛事、赛段、运动员生成参数和演示时间线。
- `docs/`：平台架构、个人开发任务书和本指南。
- `scripts/`：Windows 安装及启动脚本。
- `README.md`：项目总说明。

以下内容不上传，由每台电脑自行生成：

- `.venv/`：Python 虚拟环境。
- `.runtime/`：本机便携运行环境。
- `frontend/node_modules/`：Node 依赖。
- `frontend/dist/`：前端构建结果。
- `.vite/`、日志和缓存。

## 3. 新电脑准备

需要安装：

- Visual Studio Code。
- Git for Windows。
- Python 3.11 或更新版本。
- Node.js LTS。

在 PowerShell 逐条检查：

```powershell
git --version
python --version
node --version
npm.cmd --version
```

## 4. 克隆和安装

在准备存放项目的目录打开 PowerShell，逐条执行：

```powershell
git clone https://github.com/Maren-hub/marathon-monitor.git
```

```powershell
cd marathon-monitor
```

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

安装完成后，项目中会生成 `.venv` 和 `frontend/node_modules`，这是正常现象。

## 5. 启动平台

在 VS Code 第一个终端运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-backend.ps1
```

看到 `Uvicorn running on http://127.0.0.1:8000` 后保持终端运行。

在第二个终端运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-frontend.ps1
```

看到 `Local: http://127.0.0.1:5173/` 后访问：

- 平台：<http://127.0.0.1:5173/>
- 接口文档：<http://127.0.0.1:8000/docs>

停止服务时，在对应终端按 `Ctrl + C`。

## 6. 首次验收清单

- 页面顶部能看到赛事名称和天气。
- 重置后显示 120 名未完赛运动员并处于暂停状态。
- 点击继续后，运动员开始移动。
- 可注入聚集、跌倒和体征异常事件。
- Cesium 能显示赛道、运动员和无人机。
- 右侧能显示报警并确认处置。

每名成员完成后，将“成功截图＋遇到的问题”发到小组群，不需要立即改代码。

## 7. 确定分工后的协作方式

开始一项任务前：

```powershell
git switch main
git pull origin main
git switch -c feature/任务英文简称
```

例如：

```powershell
git switch -c feature/cesium-route
```

完成并测试后：

```powershell
git add .
git commit -m "说明本次完成的功能"
git push -u origin feature/任务英文简称
```

随后在 GitHub 创建 Pull Request，由项目负责人检查后合并。不要使用 `git push --force`，不要四个人同时直接向 `main` 推送。

## 8. 数据和安全规则

- 当前赛事和健康数据均为合成数据。
- 不向仓库上传真实姓名、手机号、定位轨迹或健康信息。
- 不上传账号密码、访问令牌、`.env` 或私钥。
- 不手动上传 `.venv`、`.runtime` 和 `node_modules`。
- 不把“模拟功能”描述为已经完成真实赛事部署。
