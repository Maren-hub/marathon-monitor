# 个人原型开发任务书：伪马拉松全流程演示

## 1. 个人任务目标

在现有 Vue + FastAPI + Cesium 骨架上，制作一个 5～6 分钟可连续演示的“伪马拉松数字孪生原型”。演示应覆盖：赛事开始、人员移动、局部聚集、跌倒、体征异常、报警确认、救援调度、终点聚集和赛后复盘。

本阶段使用合成数据，不声称是真实赛事数据，不将合成心率阈值用于医学诊断。

## 2. 最终演示故事

1. 指挥中心载入 42.195 km 逻辑赛道、5 个赛段、120 名模拟参赛者、2 架无人机和 4 个医疗组。
2. 起跑阶段人员集中，系统优先展示 S1、S2 的聚集风险。
3. S2 出现局部聚集，系统报警并调整无人机任务。
4. 人员进入中程后逐渐分散，监测重点转向综合安全。
5. S3 的 A018 出现跌倒，系统融合视频与模拟加速度信息，定位事件并派遣附近医疗组。
6. S4 的 A027 出现持续高心率和配速下降，系统提升健康风险并请求无人机复核。
7. 终点区域出现聚集，系统同时关注疏散和身体异常。
8. 赛事结束后展示事件总数、处置状态和响应时间。

## 3. 数据来源

- `data/demo_scenario.json`：赛事、赛段、资源、代表性参赛者、时间线和演示指标。
- `backend/app/simulation.py`：当前实时模拟器。
- 后续真实路线可使用 GeoJSON 替换现有逻辑坐标。
- 后续识别结果应通过统一事件接口接入，而不是直接写死在前端。

## 4. 分阶段开发任务

### 阶段 A：读懂并稳定现有骨架（0.5～1 天）

- 独立启动前端与后端。
- 打开 `/docs`，逐个调用健康检查、快照、事件注入、暂停和重置接口。
- 在纸上画出 `simulation.py → FastAPI → WebSocket → Vue → Cesium` 数据流。
- 修改一个参赛者数量或模拟速度，确认自己知道数据从哪里变化。

验收：不看他人操作，也能启动、解释和重置当前系统。

### 阶段 B：场景数据化（1～2 天）

- 为模拟器增加从 `demo_scenario.json` 读取配置的能力。
- 将参赛人数从硬编码改为配置项。
- 保留随机种子，使每次重置后的演示结果可复现。
- 在页面显著位置显示“合成数据演示”。

验收：修改 JSON 后，赛事名称、人数、速度和天气会随之变化。

### 阶段 C：自动时间线（2 天）

- 新增“自动演示”按钮。
- 根据 `timeline.demo_second` 自动触发聚集、跌倒和体征异常。
- 显示当前演示阶段、下一个事件和已播放进度。
- 支持开始、暂停、继续、重置和 1×/2×速度。

验收：不手动点击事件按钮，也能完整播放 5～6 分钟故事。

### 阶段 D：赛事资源和处置闭环（2～3 天）

- 地图显示医疗点、补给点、固定摄像头和无人机起降点。
- 新增医疗队状态：待命、出动、到达、处置完成。
- 紧急事件生成后，选择距离或赛道里程最近的可用医疗组。
- 在 Cesium 上绘制事件点到医疗点的演示救援路线。
- 报警状态改为：新建、已确认、已派遣、处置中、已完成。

验收：一次跌倒事件能够从发现一直流转到处置完成。

### 阶段 E：完整态势页面（2 天）

- 顶部：赛事时间、完赛进度、在线人数、无人机数量、未处理报警。
- 左侧：赛段风险、人数、当前监测重点。
- 中部：三维地图、人员、资源、事件和救援路线。
- 右侧：事件时间线及处置按钮。
- 底部或弹窗：参赛者心率/配速曲线、赛事统计和复盘摘要。

验收：观众不听讲解，也能大致看懂当前发生了什么。

### 阶段 F：可验证指标（1～2 天）

- 记录事件创建时间、报警时间、确认时间、派遣时间和完成时间。
- 计算报警延迟、确认用时和处置用时。
- 增加固定巡检与动态巡检两种模式。
- 对同一演示脚本运行两种模式，输出高风险事件发现时间对比。

验收：平台不仅“看起来会动”，还能导出至少一张对比结果表。

### 阶段 G：录制演示视频（0.5～1 天）

- 片头 20 秒：问题背景和系统定位。
- 结构 30 秒：说明三维赛道、视频、手环、无人机和指挥中心的数据关系。
- 主演示 3～4 分钟：按时间线连续播放三个风险事件及处置。
- 结果 40 秒：展示事件统计和策略对比。
- 结尾 20 秒：说明当前为合成数据原型及未来真实数据接入方式。

验收：视频总长控制在 5～6 分钟，画面无报错，解说不把模拟能力说成已落地能力。

## 5. 优先级

### 必须完成

- 自动时间线。
- 聚集、跌倒、体征异常三类事件。
- 事件定位和状态流转。
- 医疗资源展示及模拟派遣。
- 可复现的演示数据。
- 5～6 分钟演示视频。

### 有时间再完成

- 心率和配速曲线。
- 真实 GeoJSON 路线。
- 固定巡检与动态巡检对比。
- 事件回放。

### 暂时不做

- 自研手环硬件。
- 真实无人机视频实时推流。
- 真实医学判断。
- 完整 3D Tiles 城市建模。
- 大规模数据库和复杂账号权限。

## 6. 每日记录模板

每天结束前记录四项内容：

1. 今天完成的可见成果。
2. 修改的文件和接口。
3. 遇到的问题及解决方法。
4. 明天的最小目标。

不要只写“学习了 FastAPI”或“学习了 Cesium”，应写成“完成 `/api/snapshot` 调用并在 Cesium 显示 5 个赛段”。

## 7. 原型完成标准

原型达到以下条件即可用于本阶段汇报：

- 可在另一台电脑按照 README 启动。
- 重置后可以重复播放同一场景。
- 关键数据来自配置或后端，而不是散落在前端页面。
- 每个报警都能定位到赛段，必要时关联参赛者。
- 至少一个报警能完成医疗派遣和处置闭环。
- 能区分现有功能、模拟功能和未来计划。
- 有一组可计算的过程指标。
